# Lean proofs for bumpalo

Some of bumpalo's functions are verified with flux but marked `#[proven_externally]`: flux turns
their verification conditions (VCs) into Lean, and the proofs here discharge them. These are
functions whose arithmetic (mostly powers of two and `%` by a variable) is true but too hard for
the SMT solver.

## Running

`Cargo.toml` sets `lean = "check"`, so `cargo flux` regenerates the VCs and checks every proof with
`lake build`. A proof that uses `sorry` (directly or through a lemma) is rejected.

flux puts this project in `<working directory of rustc>/lean_proofs`. In a standalone checkout of
bumpalo that is this directory. When bumpalo is a member of a larger workspace, rustc runs from the
workspace root, so point flux here explicitly, e.g. from `research/`:

```sh
FLUXFLAGS="-Flean-dir=bumpalo" cargo flux
```

## Layout

- `LeanProofs/Flux/`: generated by flux on every run (VCs, `defs` functions, structs). Don't edit.
- `LeanProofs/User/Proof/`: the proofs, one file per `#[proven_externally]` function.
- `LeanProofs/User/Lib/`: lemmas shared by the proofs.

## Proofs

| Rust item (`src/lib.rs`) | Proof | What it proves |
|---|---|---|
| `Bump::try_alloc_layout_fast` | `User/Proof/BumpMINALIGN0TryAllocLayoutFastProof.lean` | A bump allocation returns a pointer in the current chunk with room for `size` bytes, aligned to `align` (`allocated(..)`), and stores back a finger that satisfies `bump_finger`. Covers all three arms of `match layout.align().cmp(&MIN_ALIGN)`. |
| `Bump::new_chunk_memory_details` | `User/Proof/BumpMINALIGN0NewChunkMemoryDetailsProof.lean` | The `NewChunkMemoryDetails` invariants: `align` and `payload` are multiples of 16 and `size == payload + FOOTER_SIZE`, in both the power-of-two and the page-rounding branch. |
| `align_weaken` | `User/Proof/AlignWeakenProof.lean` | Lemma: a multiple of a power of two `big` is a multiple of any smaller power of two `small` (for `big <= isize::MAX + 1`). |
| `ptr_align_weaken` | `User/Proof/PtrAlignWeakenProof.lean` | Lemma: `align_weaken` for a pointer's address. |
| `ptr_align_add` | `User/Proof/PtrAlignAddProof.lean` | Lemma: an `align`-aligned address plus a multiple of `align` is `align`-aligned. |

The three lemma functions are `#[cfg(flux)]` and called (under `#[cfg(flux)]`) from `Bump::shrink`,
so flux can check the alignment of the pointers it returns with SMT.

`User/Lib/Pow2.lean` has the power-of-two facts the proofs share:

- `pow2bv_ge16_mod16` / `pow2_int_ge16_mod16`: a power of two that is at least 16 is a multiple of 16.
- `pow2bv_dvd` / `pow2_int_dvd`: a power of two divides any larger power of two (below `2^64`).

## Assumptions

- **`debug_assert!`s are not used.** flux treats the code after `debug_assert!(c)` as knowing `c`,
  but release builds don't check it. Each proof was also done against the VC emitted with the
  function's `debug_assert!`s removed, and in the real VC the asserted facts are explicitly ignored.
- **`bv_decide`.** The lemmas in `Lib/Pow2.lean` use `bv_decide`, so the proofs that use them
  (`new_chunk_memory_details` and the alignment lemmas) also rely on the axioms `Lean.ofReduceBool`
  and `Lean.trustCompiler` (Lean's compiled code checks the SAT certificate). The
  `try_alloc_layout_fast` proof only uses Lean's standard axioms (`propext`, `Classical.choice`,
  `Quot.sound`).
- **Trusted flux specs the VCs rely on.**
  - `Bump::bump_finger` (trusted): the bump finger of a chunk owned by a `Bump<MIN_ALIGN>` is
    `MIN_ALIGN`-aligned. This can't be a `ChunkFooter` invariant because `MIN_ALIGN` is a parameter
    of `Bump`.
  - The extern spec for `usize::next_power_of_two` in `src/extra_flux_specs.rs`.
